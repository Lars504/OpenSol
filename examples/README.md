# open_sol examples

Model files (`<folder>/*.json`, one folder per physics area plus `multiphysics`) and standalone scripts that exercise
the framework. They live outside the `open_sol/` package so the library is purely framework code — they are not
listed in `structure_conventions.md`; this file indexes them instead. Install notes and quickstarts: the
top-level `README.md`.

Each script prepends the repo root to `sys.path` (redundant after `pip install -e .`) then runs from the repo root via
`python examples/<folder>/<name>.py` (scripts exist in `em` and `multiphysics` and as `headless_run.py`; the other
folders hold model files only). The scripts run on the GPU (cupy) and
write their PNG figures to the current working directory. `thin_film.py`, `plasmonic_gold.py` and
`tfln_ring_resonator.py` run a second, empty-domain or bus-only reference simulation. `ring_thermo_optic_sharkfin.py`
steps the coupled FDTD + heat model at every wavelength of an up and a down sweep, and `tfln_ring_thermo_optic.py` needs scipy and runs
the longest: several FDFD + heat solves per wavelength at each input power (the log gives each wavelength's iteration
count).

`headless_run.py` is the headless path (no GUI, the one agents use): a template, `api.check` (CPU), `api.run` (GPU)
and reading the `Results` (summary, a feature result, a field). The CLI does the same on a model file:
`python -m open_sol check examples/em/<name>.json`, then `python -m open_sol run examples/em/<name>.json --figures`
(report, results and figures in `<model dir>/<model stem>_out`).

The three original EM examples also come as GUI model files (`em/<name>.json`): open one with
`python -m open_sol.gui examples/em/<name>.json` or File → Open. They mirror the scripts with three
differences: `plasmonic_gold.json` is the particle run alone, so its `scattered_*` (outward) and `absorbed_*`
(inward) flux boxes give power in a.u., not divided by the incident spectrum (the script's empty-domain reference
pass turns them into Q_sca / Q_abs); `thin_film.json` sweeps
`n_film` over 1 (empty reference) and 1.5 instead of dividing spectra (compare the two runs in the Sweep tab);
and the models store field snapshots during the run, so the Snapshot slider shows the pulse.

`em/tfln_ring_resonator.json` is the GUI version of the TFLN ring: one run with the library materials
`lithium_niobate_z_cut` (bus and ring) and `silica` (cladding). Instead of the script's reference pass it has an
`input_flux` monitor between the source and the ring (compare it with `through_flux`; the dips are the resonances),
and instead of the on/off-resonance pass its `field_maps` DFT monitor covers 1532-1568 nm in 2 nm steps, a little
over one free spectral range, so one map lies within 1 nm of a resonance. The `n_eff`, `core_fraction` and `w_mode`
parameters are the bus-mode values the script prints; update them when the waveguide width or a material changes.

`em/tfln_ring_resonator_fdfd.json` is the same ring (geometry, materials, ring loss, 25 nm mesh) in the frequency
domain (`em_fdfd_ez`, `frequency_domain` study): one sparse direct solve per wavelength, 73 wavelengths over
1532-1568 nm in 0.5 nm steps. A `mode_source` launches the bus mode toward +x only, so no reference run is needed:
`through_port` `fraction_positive` is the through-port transmission and `input_port` `fraction_negative` the power the
ring reflects back (Spectra tab, pick the Quantity); `ring_probe` gives the intracavity |E_z| (Quantity `abs`), and every
wavelength stores an |E_z| snapshot (the Snapshot slider steps through the wavelengths). There is no ring-down to
wait for, so `round_trip_loss` can go toward a real high-Q ring at no extra cost per solve (the dips narrow: shrink
the wavelength step). Switch the study to Stationary to solve `lambda0` alone, e.g. an on-resonance map. Size: ~3.3e5
unknowns, solved by the Automatic `sparse_direct` linear solver with host SuperLU (scipy). For a broadband spectrum
the FDTD model is usually cheaper (one run gives every wavelength).

`multiphysics/tfln_ring_thermo_optic.json` is that FDFD ring plus a `heat` physics: `em_heat_joule` turns the power the
ring absorbs into heat, which leaves through the buried oxide (`out_of_plane_convection`, h = k_silica / t_box on a
600 nm film), and `heat_em_thermo_optic` feeds the temperature back into the permittivity. Its study is a coupled
`frequency_domain` scan: 61 wavelengths blue to red over `lambda_cold` - 3 nm .. + 12 nm, each an FDFD + heat fixed
point continued from the previous wavelength, with the study `relaxation` = `w_relax` = 1 / (1 + `P_in` / `P_relax`)
damping the hot branch, and a parameter sweep of `P_in` over 1 (cold reference) and 4000 W/m. Set `lambda_cold` to
the cold through-port dip first (a placeholder 1550 nm; the script finds it, or read it off
`em/tfln_ring_resonator_fdfd.json`). Sweep tab: Result `em.through_port`, series `fraction_positive`, overlays the cold
dip and the 4000 W/m thermal triangle; 'Derived value vs wavelength' `dT_ring` (mean ring temperature rise) and
`A_ring` (fraction of `P_in` the ring absorbs) per power. The Snapshot slider steps through the last power's |E_z| and
T maps. Switch the study to Stationary for one solve at `lambda0` (keep `P_in` low there, or lower its relaxation:
the plain fixed point oscillates once the thermal shift exceeds about a linewidth). The script
`multiphysics/tfln_ring_thermo_optic.py` locates `lambda_cold` (the model without its sweep at 1 W/m over one free
spectral range), runs the sweep with `api.run`, prints the dip shift and ring temperature per power and saves the
overlays (`Results.sweep_figure`) and the T / |E_z| maps of the hottest wavelength.

The GUI's Examples menu lists every model file (`*.json`) in a subfolder of this folder, grouped by its physics types
and titled by the model's `title` (its `description` is the tooltip and shows on the model node). Files are not
validated for the menu, so an example this machine cannot run (e.g. a cuDSS solver without a GPU) is still listed and
its problems show when it is opened. It opens an untitled copy, so saving never overwrites the example. Files that are
not readable JSON are named in the Messages tab; selftest `examples_validate` fails on any example that does not
validate.

Naming: this file lists examples by file stem, the GUI by `title`. Menu path: Examples -> folder label (`em` =
Electromagnetics 2D, `em3d` = Electromagnetics 3D, ...) -> physics type label (only when the folder holds several,
e.g. 'Electromagnetic Waves, frequency domain (2D, electric field out of plane)' for em_fdfd_ez; models with several
types follow under 'label + label') -> title, sorted alphabetically. Titles: analytic benchmarks start with
'Analytic: ', then what the model shows, then the method / study in parentheses, e.g. `analytic_fdfd_eigen_slab_q` =
'Analytic: leaky Fabry-Perot slab resonance and Q (FDFD eigenfrequency)'; models without a reference drop the prefix.
The tooltip ends with the relative file path, so hovering a title gives the stem.
